# Plan 2 — API (Hono บน Cloudflare Workers) + ฐานข้อมูล D1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** มี REST API แบบอ่านอย่างเดียวบน D1 ที่คืนข้อมูลเหมือนกับ fallback JSON ทุกประการ และให้เว็บเรียก API จริงได้ (ล่มแล้วตกไปใช้ fallback พร้อมแบนเนอร์) ทั้งหมดรันและทดสอบในเครื่องได้โดยไม่ต้องมีบัญชี Cloudflare

**Architecture:** `packages/shared` เป็นแหล่งความจริงเดียว: ตัวสร้างข้อมูลเดิมสร้างทั้ง fallback JSON และ seed SQL, และฟังก์ชันสร้าง payload (ทำงานบน `Dataset` ในหน่วยความจำ) ย้ายมาอยู่ที่นี่ เว็บใช้ตอน fallback ส่วน API ใช้ SQL บน D1 ที่ให้ผลเท่ากัน มี test เทียบผลสองฝั่งโดยตรง (contract) การ deploy จริงไปอยู่แผน 3

**Tech Stack:** TypeScript, Hono 4.13, zod 4.6, Wrangler 4.158 (Miniflare ในตัว, D1 local), `@cloudflare/vitest-plugin` 1.6 + Vitest 5.1 (ที่ repo ใช้อยู่), Node ≥ 22 (เครื่องนี้ 26) — เวอร์ชันตรวจจาก npm เมื่อ 2026-11-09

**Spec:** `docs/specs/2026-11-09-condoscope-design.md` (ข้อ 13 มีผลเหนือข้ออื่น; ข้อ 6–7, 9, 10 ขั้น 4) + `docs/original-spec.md` ข้อ 7–8, 16–17

**ก่อนเริ่ม:** แผน 1 ต้องถูก merge เข้า `main` แล้ว (ถ้ายังไม่ merge ให้แตก `feat/plan-2` จาก `feat/plan-1`) ไม่ต้องมีบัญชี Cloudflare จนถึงแผน 3

## งบโควตาฟรี (ตรวจจากเอกสาร Cloudflare 2026-11-09 — แผนออกแบบให้อยู่ในกรอบนี้)

- **D1 ฟรี:** อ่าน 5 ล้านแถว/วัน · เขียน 100,000 แถว/วัน · 500 MB/ฐานข้อมูล · ค่า "rows read" นับแถวที่สแกน ไม่ใช่แถวที่คืน → ต้องมี index และห้ามสแกนทั้งตาราง · 50 query ต่อ 1 request · 100 bound parameters ต่อ query · 1 statement ≤ 100 KB
- **Workers ฟรี:** 100,000 request/วัน · CPU **10 ms** ต่อ request
- ผลต่อการออกแบบ: (ก) explorer ของโครงการใหญ่สุดอ่านราว 700–1,400 แถว/ครั้ง → ประมาณ 3,500–7,000 ครั้ง/วันก่อนเต็ม จึงต้องมี `Cache-Control` และใช้ SQL ชุดเดียวต่อ endpoint (ไม่ N+1) (ข) seed 1 รอบเขียนราว 12,000+ แถว (รวม index) → **ห้าม re-seed ฐานข้อมูลจริงวนซ้ำ** (ค) แปลงแถว→JSON ต้องเบา (ไม่ parse ด้วย zod ทีละแถว) เพราะ CPU 10 ms; วัดจริงตอน deploy

## Global Constraints

- งบ 0 บาท: free tier และ open source เท่านั้น ห้ามบริการที่ต้องผูกบัตร
- API อ่านอย่างเดียว ไม่มี endpoint เขียนข้อมูล; ไม่ทำระบบจำกัดจำนวน request (สเปกข้อ 13.4)
- ใช้ `zod` ตรวจ query/params; **ทุก SQL ใช้ parameter binding** (ห้ามต่อสตริงค่าจากผู้ใช้เข้า SQL)
- error รูปแบบเดียว `{ error: { code, message } }`; ห้ามรั่วรายละเอียดภายใน (stack, ข้อความ SQL)
- CORS อนุญาตเฉพาะ origin ของ GitHub Pages (`https://rawinan-txt.github.io`) และ localhost; ข้อมูลสาธารณะมี header `Cache-Control`
- `GET /api/projects/:id/explorer` คืนรูปทรงตึก + ห้องทั้งหมดของโครงการ **ใน request เดียว** (สเปกข้อ 13.14); **ไม่มี** `GET /api/buildings/:id/views` (ข้อ 13.2)
- ตัดตาราง `building_views`, `unit_polygons`, `floor_plans`, `floor_plan_hotspots`, `unit_images` (ข้อ 6, 13.1); ภาพภายในอยู่ในตาราง `unit_type_images`
- ข้อมูลสำรองต้องสอดคล้องกับ seed; **ห้ามแสดงข้อมูล fallback ว่าเป็น live** (แบนเนอร์ "Demo Fallback Mode" ทุกครั้งที่ใช้ fallback)
- ห้ามมี secret ใน frontend: `VITE_API_URL` เป็น URL สาธารณะเท่านั้น
- test ใช้ D1 จริงใน Miniflare ห้าม mock D1 (ยกเว้นตัวห่อนับจำนวน query และ DB ที่จงใจพังในไม่กี่เคส)
- ทำงานบน branch `feat/plan-2`; ทุก commit ลงท้ายด้วยบรรทัด `Co-Authored-By` ที่ระบบกำหนดให้ในตอนนั้น (ชื่อโมเดลอาจเปลี่ยนระหว่างงาน)

## Review Focus

1. **ข้อความค้นหามีอักขระพิเศษ:** `%`, `_`, `\`, `'`, `"; DROP TABLE units;--`, ช่องว่างล้วน, ภาษาไทย, ยาวเกิน 100 ตัว → ต้องจับคู่แบบตัวอักษรจริง (ไม่ใช่ wildcard) หรือตอบ 400 และตารางต้องไม่เสียหาย ไม่เคยเป็น 500 → Task 5 (ผลตรงกับ fallback) และ Task 6 (HTTP)
2. **id/พารามิเตอร์รูปผิด:** `/api/units/abc`, `/0`, `/-1`, `/1.5`, `/1e3`, `/99999999999999999999`, `minPrice>maxPrice`, `minPrice=-1`, `limit=0`, `limit=51`, `status=SOLD`, `floor=abc` → 400 รูปแบบ error เดียว ไม่เป็น 500 → Task 6
3. **id ถูกรูปแต่ไม่มีอยู่ / ตัวกรองไม่เจอ:** `/api/units/999999` → 404; `?floor=999` → 200 พร้อมรายการว่าง (ไม่ใช่ 404) → Task 6
4. **CORS ปลอม:** `https://rawinan-txt.github.io.evil.com`, `http://localhost.evil.com`, `null` → ไม่ได้ header อนุญาต; preflight `OPTIONS` ใช้ได้; request ที่ไม่มี Origin (curl) ทำงานปกติ → Task 7
5. **API ล่ม/ช้า/ตอบขยะ:** timeout เกิน 5 วินาที, 500, 200 ที่เป็น HTML (URL ผิดไปโดนหน้า 404 ของ GitHub Pages), JSON เสีย → หน้าเว็บตกไปใช้ fallback + แบนเนอร์ ไม่ค้าง ไม่พัง; ส่วน 404/400 ต้องเป็น "ไม่พบข้อมูล" ไม่ใช่ fallback → Task 8 และ Task 9
