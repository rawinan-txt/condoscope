# Plan 4 — รอบ UX/UI: Explorer เต็มจอ แผงลอยโปร่งแสง และการปรับให้ใช้งานได้ทุกอุปกรณ์

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ทำให้หน้า Building Explorer เป็นประสบการณ์เต็มจอ — ตึก 3D กินพื้นที่ทั้งหน้า แผงรายการห้อง ตัวกรอง ผ่าชั้น และรายละเอียดห้องลอยทับด้านข้างแบบโปร่งแสง — โดย**ยังใช้คีย์บอร์ดและ screen reader ได้ครบ** และบนมือถือเป็น bottom sheet ส่วนแผนที่คงพฤติกรรมเดิม (กดหมุดแล้วไปหน้าโครงการ)

**Architecture:** ไม่แตะ API, ฐานข้อมูล, ตัวสร้างข้อมูล หรือ workflow — เปลี่ยนเฉพาะ `apps/web` (เลย์เอาต์, คอมโพเนนต์ overlay, กรอบกล้อง 3D, e2e และเอกสาร) คอมโพเนนต์เนื้อหาเดิม (`UnitPanel`, `Filters`, `FloorSelector`, `UnitList`, `Legend`) ย้ายเข้าไปอยู่ในกรอบ overlay ใหม่ได้โดยแทบไม่ต้องแก้ตรรกะ; state ทั้งหมดยังอยู่ใน `useExplorer`

**Tech Stack:** React 19, Tailwind 4, React Three Fiber + three (มีอยู่แล้ว), Vitest, Playwright + `@axe-core/playwright` — **ไม่เพิ่ม dependency ใหม่**

**Spec:** `docs/specs/2026-11-09-condoscope-design.md` ข้อ 4.3 (การโต้ตอบ: คีย์บอร์ด, bottom sheet บนมือถือ, Unit List/Floor Selector เป็น HTML ปกติ), 4.4, 8.1 (ลำดับหน้า — หน้าแรกเป็นหน้าค้นหา, 3D เข้าผ่านหน้าโครงการ), 8.2, 13.12 (OpenFreeMap) · รายการเดิมใน `CLAUDE.md` หัวข้อ "งานรอบ UX/UI"

**ก่อนเริ่ม:** แตก `feat/plan-4` จาก `main` (PR #3 merge แล้ว) และให้ผู้ใช้ส่ง **รายการปัญหา UX จากการทำ QA บนเว็บจริง** (ถ้ามี) มาก่อนอนุมัติ — ดู Task 8

- `BuildingView.tsx`: แถบปุ่มสลับ 3D/2D (และปุ่มเลือกอาคาร/ด้านใน 2D) อยู่เหนือพื้นที่ตึก; พื้นที่ตึก `tabIndex=0` รับลูกศร/Enter/Esc

## ความเสี่ยง

1. **`setViewOffset` กับ raycast** (ตัดสินใจ 5) — พิสูจน์ด้วย e2e ก่อนไปต่อ มีแผนถอย
2. **Overlay บังตึกจน e2e คลิกพลาด** — แก้ที่ `visibleUnits` (ตรวจ `elementFromPoint` ว่าเป็น canvas) ไม่ใช่ลดความเข้มงวดของ test
3. **คอนทราสต์บนฉากหลังที่เปลี่ยนตลอด** — คำนวณกรณีแย่สุด (พื้นแผงทึบ ~88% ทับฉากดำ/ขาว) ใน unit test ไม่พึ่ง axe อย่างเดียว (axe เห็นพื้นหลังแค่ในหน้า ไม่เห็นสีใน canvas)
4. **ประสิทธิภาพ `backdrop-filter`** — ใช้เฉพาะ ≥ md และ `motion-safe`; ใน e2e ใช้ software WebGL จึงวัด FPS จริงไม่ได้ **ต้องให้ผู้ใช้ลองบนเครื่องจริง** (จดไว้ใน Task 9)
5. **focus trap / screen reader บน bottom sheet** — ไม่ทำ modal (ไม่ trap focus) ให้เป็นแค่ region ที่ขยาย/ย่อได้ จึงไม่มีกับดักคีย์บอร์ด
6. **ทำให้ test case QA/BA ของผู้ใช้ล้าสมัย** — ห้ามแก้เอง ต้องแจ้งผู้ใช้ (ดู Task 9)
