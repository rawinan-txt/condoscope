# Test Plan — CondoScope

> เวอร์ชัน 0.1 (ร่าง) · ผู้ทดสอบ: rawinan-txt · อ้างอิงสเปก `docs/specs/2026-11-09-condoscope-design.md`

## 1. วัตถุประสงค์
ยืนยันว่า CondoScope ทำงานตามความต้องการในสเปก โดยเฉพาะ**เกณฑ์สำเร็จข้อหลัก: ผู้ใช้เลือกห้องจากตัวตึกได้ และข้อมูลที่แสดงตรงกับห้องที่เลือก** รวมถึงทำงานได้บนอุปกรณ์ที่หลากหลาย และยังใช้งานได้เมื่อบริการฟรีล่ม

## 2. ขอบเขต
**ทดสอบ**
- หน้าแรก การค้นหา ตัวกรอง ผลการค้นหา
- แผนที่
- หน้าโครงการ
- Building Explorer 3D และ SVG fallback (ทั้ง 5 โครงการ)
- หน้า Unit Detail, แปลนห้อง, hotspot, ภาพภายใน
- การจองจำลอง
- โหมดข้อมูลสำรองเมื่อ API ล่ม
- REST API (อ่านอย่างเดียว): ค่าที่คืน, validation, รูปแบบ error
- Responsive, accessibility พื้นฐาน, ประสิทธิภาพพื้นฐาน

**ไม่ทดสอบ** (อยู่นอกขอบเขตของระบบ)
- การชำระเงิน ระบบจองจริง ระบบสมาชิก
- Load test ระดับสูง (ระบบอยู่บน free tier)
- Security penetration test เต็มรูปแบบ (ตรวจแค่ input validation กับ SQL injection พื้นฐาน)

## 3. ประเภทการทดสอบ
| ประเภท | วิธี | เครื่องมือ |

| Automated (ถ้าทำ) | Playwright | `apps/web/e2e/` |

## 5. เกณฑ์เริ่มและจบการทดสอบ
**เริ่มเมื่อ:** deploy ครบทั้ง frontend และ API และทุกหน้าเปิดได้
**จบเมื่อ:**
- รัน test case ครบ 100%
- test case กลุ่ม **P1** ผ่านทั้งหมด
- ไม่มีบั๊กระดับ Critical หรือ High ที่ยังเปิดอยู่

## 6. ระดับความรุนแรงของบั๊ก
| ระดับ | ความหมาย | ตัวอย่าง |
|---|---|---|
| Critical | ฟีเจอร์หลักใช้ไม่ได้ หรือเว็บเปิดไม่ขึ้น | คลิกห้องแล้วแสดงข้อมูลของห้องอื่น |
| High | ฟีเจอร์สำคัญเสีย แต่มีทางเลี่ยง | ตัวกรองราคาไม่ทำงาน |
| Medium | ทำงานได้แต่ผิดเพี้ยน | การ์ดเรียงลำดับผิดบางกรณี |
| Low | ความสวยงาม หรือข้อความ | ข้อความล้นปุ่มบนมือถือ |

ลำดับความสำคัญของ test case: **P1** = ต้องผ่าน (ฟีเจอร์หลัก) · **P2** = สำคัญ · **P3** = เสริม

## 7. ขั้นตอนเมื่อเจอบั๊ก
1. ทำซ้ำให้ได้อย่างน้อย 2 ครั้ง
2. เปิด GitHub Issue ด้วย template "Bug report" ใส่ขั้นตอน ผลที่คาดหวัง ผลจริง ภาพหน้าจอ และระดับความรุนแรง
3. ใส่เลข issue ในช่อง "บั๊ก" ของ test case และตั้งสถานะเป็น ❌ Fail
4. เมื่อแก้แล้ว ทดสอบซ้ำ (re-test) แล้วเปลี่ยนสถานะ และปิด issue

## 8. ความเสี่ยง
| ความเสี่ยง | ผลกระทบ | วิธีรับมือ |
|---|---|---|
| Free tier ของ Cloudflare หรือ OpenFreeMap ล่ม | ทดสอบ API หรือแผนที่ไม่ได้ | ทดสอบโหมดสำรอง แล้วจดเวลาไว้ ค่อยทดสอบซ้ำภายหลัง |
| เครื่องทดสอบแรงไม่พอสำหรับ 3D | ผลด้านประสิทธิภาพเพี้ยน | ระบุสเปกเครื่องในผลทดสอบ |
| ข้อมูลเป็นแบบสุ่ม | ค่าที่คาดหวังเปลี่ยนได้ | อ้างอิงข้อมูลจาก seed เดียวกัน และตรวจกับ API |
